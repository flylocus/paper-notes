# Phase1 enrichment for SPIRAL (2606.23595)

Paper: SPIRAL: Learning to Search and Aggregate
Authors: Jubayer Ibn Hamid, Ifdita Hasan Orney, Michael Y. Li, Omar Shaikh, Yoonho Lee, Dorsa Sadigh, Chelsea Finn, Noah Goodman
Affiliation: Stanford University
Submitted: 22 Jun 2026
Category: cs.AI

Abstract:
Language model reasoning can be substantially improved at test time via scaffolds that scale inference compute across different primitives — sequential reasoning within a trace, independently sampled parallel traces, and aggregation of multiple reasoning traces into a final response. During post-training, however, language models are optimized only for sequential reasoning within a single trace.

We introduce Sequential-Parallel-Aggregative Reinforcement Learning (SPIRAL), a framework in which a language model is trained to use all three primitives, as part of a unified inference compute pipeline. Concretely, the language model first samples a set of independent traces in parallel, each produced through sequential chain-of-thought reasoning, and then generates a final aggregation trace conditioned on those traces; all components are optimized end-to-end against the reward of the final aggregated response. To train this system, SPIRAL uses set reinforcement learning to teach models to produce a set of traces that are collectively useful for an aggregator and standard reinforcement learning to teach models to aggregate the set into improved final responses.

Our experiments on reasoning tasks show that SPIRAL effectively scales with inference compute, outperforming GRPO by up to 11× scaling efficiency and 15% higher performance when all three compute primitives are scaled.

Key differentiators:
1. Unlike Best-of-N or self-consistency (post-hoc aggregation), SPIRAL trains the model end-to-end to produce AND aggregate traces
2. Set RL for the parallel trace production (traces must be collectively useful, not individually optimal)
3. Standard RL for the aggregation step
4. 11× scaling efficiency over GRPO — meaning for the same compute budget, SPIRAL delivers significantly better results
5. 15% absolute improvement when all three primitives scale together

Limitations (from paper context):
- "Ongoing Work" tag — still early
- Requires multi-trace training, more expensive than single-trace RL
- Aggregation quality depends on trace diversity
