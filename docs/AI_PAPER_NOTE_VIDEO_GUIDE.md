# AI 论文速记 · 视频号内容与生产规范 v1.0

**Status:** shadow mode  
**Date:** 2026-07-31  
**Brand:** AI 系统笔记  
**Upstream:** `paper-notes` publish-ready bundle  
**Default format:** 一篇论文一条视频；每天 1–2 条  

## 一句话结论

AI 论文速记视频不是把公众号 A–F 摘要念一遍，而是用 70–90 秒交付：

> 一篇论文，一个可复用判断；同时讲清方法、证据和边界。

## 1. 栏目定位

### 主要目标

建立「AI 系统笔记」的专业信任：让 AI 产品、工程、研究和 ToB 决策者快速判断一篇论文是否值得继续读、值得如何使用。

### 次要目标

- 为公众号长文提供深度承接；
- 沉淀可检索的论文判断库；
- 形成区别于“论文摘要号”和“AI 新闻号”的稳定识别。

### 明确不做

- 不追求讲完整篇论文；
- 不按 A–F 顺序朗读公众号正文；
- 不只报标题、机构、评分和涨点；
- 不把论文结论包装成已经落地的产业事实；
- 不为了热度省略样本、条件和限制；
- 不把 DARE 的“企业三问 / 行动清单”机械搬过来。

## 2. 与 DARE 视频的关系

两条内容线共用生产纪律，不共用内容语法。

| 维度 | DARE 每日判断 | AI 论文速记 |
|---|---|---|
| 核心问题 | 今天发生了什么，企业怎么办 | 这篇论文证明了什么，证据够不够 |
| 内容母体 | `news-daily` 多信号综合 | `paper-notes` 单篇论文证据链 |
| 固定主线 | Hook → 判断 → 三证据 → 推理 → 行动 | Hook → 研究问题 → 方法 → 关键证据 → 判断 → 边界 |
| 必须出现 | 企业影响、行动建议 | 方法、关键结果、限制面 |
| 视觉识别 | 纸色、红/蓝/金/绿 | 深海蓝、冷青、白、边界紫 |
| 收尾 | DARE 品牌判断句 | AI 系统笔记栏目承诺 |

共用的硬纪律：

- 每条只有一个唯一观点；
- 完整文字脚本先交申飞确认；
- 未确认不得调用 TTS；
- 正式旁白整篇一次连续生成；
- 画面跟随连续语音的自然停顿；
- 字幕、证据、视觉和技术指标必须经过 QA；
- 用户 Logo 只可等比、完整放置，不得裁切、重绘、翻译或生成替代品。

## 3. 日更产品形态

### 默认：单篇速记

- 一篇论文一条视频；
- 每天 1–2 条，最多 2 条；
- 两篇都达到 publish-ready 时，按 `paper-notes` 的主发顺序发布；
- 第一篇为「今日主论文」，第二篇为「今日加更」，不强行合并。

这样做的原因：

1. 每篇论文的证据和边界保持独立；
2. 不会为了“日更合刊”硬造两篇之间不存在的关系；
3. 封面、标题、搜索词和评论讨论都能围绕一个问题收敛；
4. 上游一篇或两篇变化时，生产流程不用改。

### 可选：双篇对读

只有同时满足以下条件才使用：

- 两篇回答同一个明确问题；
- 能提炼出一个共同判断，而不是两个摘要并排；
- 每篇至少保留一条关键证据和一个边界；
- 完整脚本不超过 100 秒。

双篇对读是周度或专题产品，不是日更默认。

## 4. 单条内容结构

### 固定七段

| 段落 | 任务 | 口播预算 |
|---|---|---:|
| 1. Hook | 用论文里的冲突、失败或反直觉结果开场 | 1–2 句 |
| 2. 研究问题 | 说明论文到底想回答什么 | 1 句 |
| 3. 方法 | 讲清它怎么验证，不念完整术语表 | 1–2 句 |
| 4. 关键证据 | 只留 2–3 个最能支撑唯一观点的数字或结果 | 3–4 句 |
| 5. 我的判断 | 把论文结果提升为一个可复用判断 | 1–2 句 |
| 6. 证据边界 | 明确样本、任务、成本或外推限制 | 1–2 句 |
| 7. 品牌收尾 | 稳定结束，不增加新事实 | 2 句 |

固定品牌收尾：

> 一篇论文，一个可复用判断。这里是 AI 系统笔记。

### 字数与时长

- 口播预算采用同一种口径计量：汉字约 260–300，或包含数字、标点和拉丁词在内的非空白字符约 340–380；
- 目标时长：70–90 秒；
- 最长：95 秒；
- 开头保留约 0.8–0.9 秒无旁白画面；
- 前 8 秒必须交付冲突和研究问题，不先念机构、作者和评分。

### 唯一高潮

全片唯一最高点放在「我的判断」，不是 Hook、评分或最大数字。

情绪曲线：

> 问题出现 → 冷静解释 → 证据推进 → 判断升维 → 主动降温讲边界 → 稳定收尾

## 5. 选题与脚本规则

### 进入视频链的上游门槛

只有同时满足以下条件的论文才能进入：

- 位于 `outputs/ready/YYYYMMDD/{paper_id}/`；
- `qa_report.md` 为 PASS；
- `preflight_report.md` blocking = 0；
- `gate5_report.md` 为 PASS；
- `evidence_ledger.json` 存在；
- 公众号主标题、判断和关键数字已经稳定。

warning 不自动阻断，但必须确认不影响视频引用的字段。

文章门禁与视频门禁必须分开命名：

- `ARTICLE_READY`：文章上游 QA / preflight / Gate5 已满足视频取材条件；
- `VIDEO_SCRIPT_DRAFT`：视频文字脚本已完成内部证据检查，等待申飞确认；
- `VOICE_ADAPTATION_DRAFT`：审核脚本已生成一一对应的字幕文本与 TTS 配音稿；
- `VOICE_SCRIPT_APPROVED`：申飞已明确确认审核脚本、字幕/口播映射和完整 TTS 配音稿；
- `VIDEO_QA_PASS`：正式视频通过视频专属 QA；
- `VIDEO_READY`：申飞人工终审后锁定唯一发布入口。

> `ARTICLE_READY` 只说明论文可以进入视频改编；`VIDEO_SCRIPT_DRAFT` 也不等于 TTS 文本已经确认。只有 `VOICE_SCRIPT_APPROVED` 才允许进入导演稿和连续 TTS。

### 证据取舍

一条视频只取：

- 1 个研究问题；
- 1 个方法机制；
- 2–3 个关键证据；
- 1 个判断；
- 1 组限制。

优先级：

1. `evidence_ledger.json` 的 `claim_evidence`；
2. `note.md` 的 D 段关键结果；
3. `note.md` 的 So What / 飞哥视角；
4. `publish_pack.md` 的标题和导语；
5. 论文 PDF 原文复核。

评分只作为角标，不作为“论文可靠”的替代证据。

### 事实与判断分层

画面和脚本都必须区分：

- `论文结论`：作者或实验直接支持；
- `我的判断`：AI 系统笔记基于证据做出的解释；
- `证据边界`：论文没有证明、暂时不能外推的部分。

禁用表达：

- “彻底解决”“已经证明通用有效”“全面超越”；
- 把单一 benchmark 写成现实生产结果；
- 把相关性、评审意见或个案写成总体成功率；
- 没有对照条件的“提升 X 倍”；
- 省略分母、基线、模型名或任务条件后仍报数字。

## 6. 标题、封面与发布文案

### 视频标题

推荐结构：

> 冲突结果：论文提出的机制或判断

要求：

- 18–30 个中文字符；
- 保留一个核心搜索词；
- 不把 arXiv 编号放进主标题；
- 不以“震惊、颠覆、炸裂、封神”制造热度；
- 问号只在论文确实回答该问题时使用。

### 封面

- 画幅：1080×1440；
- 主标题：10–18 个中文字符，最多 3 行；
- 副标题：论文机制或研究对象，最多 18 个中文字符；
- 右上或底部小字：`AI 论文速记 · arXiv:{id}`；
- 评分可作为小型可信度角标，不得大于主标题；
- 不把英文论文全标题塞进封面。

### 发布文案

固定三层：

1. 一句冲突；
2. 一句“这篇最值得带走的判断”；
3. 论文名、arXiv ID 和 2–4 个主题标签。

不把完整口播再复制一遍。

## 7. 视觉系统

### 视觉定位

关键词：研究台、证据链、冷静、可验证。

固定色彩：

- 深海蓝 `#0B1739`：主背景；
- 冷青 `#42C8FF`：论文事实 / 数字；
- 白 `#F5F7FB`：主文字；
- 边界紫 `#A78BFA`：限制与未证明；
- 判断橙 `#FFB454`：仅用于「我的判断」。

不得复用 DARE 的纸色底和红色判断线作为主视觉。

### 固定画面语法

1. Hook：一个冲突数字或结果；
2. Research Question：一句研究问题；
3. Method：一张简化方法图；
4. Evidence：2–3 个证据节点依次点亮；
5. Judgment：判断橙只在此处成为主色；
6. Boundary：紫色边界框主动降温；
7. Close：完整放置 AI 系统笔记品牌资产。

每屏只完成一个任务。观众静音观看时，也应能复述：

> 研究问题是什么、论文怎么做、最硬的结果是什么、哪里不能外推。

### 图表与论文原图

- 默认重绘为简化关系图、数字卡或对照条；
- 不自动截取整页 PDF、复杂表格或论文插图；
- 使用论文原图时必须确认授权/引用方式，并在画面标来源；
- 不为了“科技感”生成与论文无关的机器人、芯片或数据流背景；
- AI 系统笔记 Logo 使用用户提供的权威资产，完整、等比放置。

## 8. 声音与导演规则

### 演绎基线

- 75% 冷静研究讲解；
- 20% 问题驱动；
- 5% 判断落点；
- 85% 正常表达，15% 强调；
- 不播音腔，不用连续反问，不模拟具体主播口癖。

### Voice Adaptation：字幕与口播双轨

论文视频把配音问题优先当作脚本层问题，不期待 TTS 自动猜对中英混读。

同一条内容允许有三层文本：

| 文本层 | 用途 | 规则 |
|---|---|---|
| 审核脚本 `review_text` | 事实、判断和边界真源 | 供申飞与审稿 Agent 核验 |
| 字幕文本 `subtitle_text` | 屏幕显示、搜索和术语识别 | 保留论文原词、标准拼写和必要缩写 |
| 配音文本 `voice_text` | 连续 TTS 输入 | 中文语流优先，品牌保留英文，概念与数字口语化 |

双轨不是自由改写。每个配音单元必须和审核脚本一一对应，并记录：

- `source_text`
- `subtitle_text`
- `voice_text`
- `adaptation_reason`
- `protected_facts`
- `lexicon_terms`

允许的差异：

- `SkillBoost` 字幕保留原词，口播按英语单词边界读作 `Skill Boost`；
- `BFCL` 字幕保留缩写，口播为 `B F C L 工具调用基准`；
- `Generalization Gap` 字幕可保留原词，口播优先说“泛化间隙”；
- `37.7 → 48.5` 字幕保留数字，口播说“从三十七点七提升到四十八点五”；
- 不影响事实的指代替换，例如字幕 `Claude Sonnet 4`，口播“Claude 的 Sonnet Four 模型”。

禁止的差异：

- 改变数字、分母、基线、模型、任务或实验条件；
- 把“约”“示例”“两个案例”等限定词删掉；
- 把 `Reject` 弱化成普通低分，或把个案写成总体结论；
- 为了顺口增加审核脚本中不存在的新判断；
- 字幕保留事实条件、口播却省略该条件。

### 术语适配规则

1. 品牌、机构、模型和论文/框架名原则上保留英文发音；
2. 技术概念优先中文化，第一次出现可在字幕并列英文，后续只说中文；
3. 数字全部改为自然中文口语，字幕仍可保留阿拉伯数字；
4. 缩写若必须口播，逐字母读，并补一个中文功能说明；
5. 同一条视频中，同一术语只能采用一种已确认读法；
6. 术语词典真源：`config/video_voice_lexicon.yaml`。

专有词必须有显示文本、发音目标和 provider-specific TTS 文本三层：

- Agent、SkillBoost、BFCL、Claude、Codex、GPT-5.6 Sol 等逐期进入审听清单；
- 字幕保留标准拼写；
- 词典中的 `speak_default` 是发音目标，不是跨 TTS provider 的保证；
- provider-specific 发音只存在于 `provider_overrides` 或最终 `voice_text`；
- `pending_review` 术语不得直接锁为正式发音；
- 换模型后重新人工审听。

### 连续旁白规则

- 审核脚本、字幕/口播映射和完整配音稿经申飞明确确认后，状态才可进入 `VOICE_SCRIPT_APPROVED`；
- 正式旁白整篇一次提交 TTS；
- 原始连续音频只能有一个；
- 不按场景分段合成后拼接；
- 只清理首尾惰性静默，不切割内部语流；
- 画面提前下一句约 0.25–0.40 秒进入；
- 字幕与语音同步进入。

## 9. 从 paper-notes 到视频的生产流程

### Stage 0：上游验收

- Owner：paper-notes operator；
- 输入：当天任务卡和论文 ready bundle；
- 检查：文章 QA / preflight / Gate5 / evidence ledger；
- 输出：`ARTICLE_READY` 取材资格；
- 禁止：把文章 PASS 当成视频脚本确认或视频发布资格。

### Stage 1：视频 Brief

- Owner：视频编辑 Agent；
- 输入：`ARTICLE_READY` bundle；
- 输出：`video-brief.json`；

为每篇生成一份 brief，至少包含：

- `paper_id`
- `video_title`
- `cover_title`
- `research_question`
- `one_judgment`
- `method_in_one_sentence`
- `evidence_1..3`
- `boundary`
- `protected_terms`
- `source_locations`

### Stage 2：完整文字脚本

- Owner：视频编辑 Agent；
- 输入：`video-brief.json` + evidence ledger；
- 输出：审核脚本及其 `Script Check` 勾选记录、状态 `VIDEO_SCRIPT_DRAFT`；正式自动化后可再拆为独立 `script-check.md`；

先写事实与判断可审的完整文字脚本，不直接把中英混排稿送入 TTS。脚本必须通过：

- 唯一观点检查；
- 数字与限定条件回查；
- “方法 / 证据 / 边界”三项齐全；
- 公众号正文复述率检查；
- 口语自然度检查。

### Stage 3：Voice Adaptation

- Owner：视频编辑 Agent；
- 输入：`VIDEO_SCRIPT_DRAFT` + `config/video_voice_lexicon.yaml`；
- 输出：逐单元字幕/口播映射、完整连续配音稿、术语审听清单、状态 `VOICE_ADAPTATION_DRAFT`；
- 任务：品牌和框架名保留标准英文发音；技术概念中文化；数字中文口语化；事实与条件保持一一对应。

Voice Adaptation 只负责“怎么念”，不得改变“说了什么”。如适配过程发现原审核脚本不适合口播，只能返回 Stage 2 修稿。

### Stage 4：申飞双轨确认

- Owner：申飞；
- 输入：审核脚本、`Script Check`、字幕/口播映射、完整连续配音稿；
- 输出：明确确认记录、状态 `VOICE_SCRIPT_APPROVED`；
- 这是硬门槛。

> 未收到申飞对审核脚本与完整配音稿的明确确认，不得制作正式导演稿、不得调用 TTS、不得生成正式视频。

确认后只要进入 TTS 的 `voice_text` 发生变化，都必须重新完成语义对齐检查并由申飞重新确认；不得以“只是发音写法或过渡句”为由绕过。仅 provider 内部不改变听感与语义的 SSML/发音参数调整，可在术语短审通过后记录为 provider override。

### Stage 5：导演稿与画面

- Owner：视频制作 Agent；
- 输入：`VOICE_SCRIPT_APPROVED` 审核脚本、字幕稿与配音稿；
- 输出：导演稿、场景稿、字幕草稿和封面；

- 标出信息块、逻辑关系、能量和唯一重点；
- 生成场景稿、字幕草稿和封面；
- 先检查静音可理解性；
- 不修改已确认脚本中的事实、数字和边界。
- 如必须修改口播，返回 Stage 3–4，不得在导演稿中暗改。

### Stage 6：连续 TTS

- Owner：视频制作 Agent；
- 输入：`VOICE_SCRIPT_APPROVED` 完整 `voice_text` + provider override；
- 输出：一个原始连续音频 + TTS 生成报告；

- 一次请求；
- 一个原始连续音频；
- 对 `pending_review` 术语先做短审；正式旁白仍为一次连续请求；
- 完整审听时同时对照字幕文本和审核脚本；
- 读取真实时长和自然停顿。

### Stage 7：合成与 QA

- Owner：视频制作 Agent + 人工 QC；
- 输入：连续音频、导演稿、字幕和画面；
- 输出：候选 MP4、`video-qa-report.md`、状态 `VIDEO_QA_PASS`；

- 画面跟随连续语音；
- 字幕同步；
- 输出 MP4、封面、发布文案、SRT；
- 抽帧、黑帧、越界、Logo、响度、解码和时长检查。

### Stage 8：锁定发布入口

- Owner：申飞；
- 输入：`VIDEO_QA_PASS` 候选 + 完整人工观看和审听；
- 输出：`FINAL.md` + 状态 `VIDEO_READY`；
- 通过人工终审后，在 `FINAL.md` 只指定一个 canonical MP4。历史候选保留，但不得与正式入口并列。

## 12. 30 天试运行

### 频率

- 保持 paper-notes 实际产量：每天 1–2 条；
- 不为了凑两条降低上游论文门槛；
- 同日两条间隔发布，不连续轰炸。

### 观察指标

以账号自身基线做周度比较，不先套行业平均值：

- 前 3 秒留存；
- 平均观看时长与完播率；
- 转发、收藏及其占播放比例；
- 高质量评论数：是否围绕方法、证据或应用边界讨论；
- 主页访问、关注转化和公众号承接；
- 单条制作耗时与返工次数。

### 每周复盘

每周只回答四个问题：

1. 哪类 Hook 留住人，但没有牺牲准确性？
2. 哪类证据画面最容易被静音理解？
3. 哪些专业词造成掉点或听感问题？
4. 哪一条判断带来最多收藏、转发和专业评论？
